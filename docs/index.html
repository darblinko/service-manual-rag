service-manual-rag

Answers technician questions from equipment service manuals with cited passages, using Qdrant vector search, optional Neo4j graph search and Reciprocal Rank Fusion. A LangGraph supervisor routes multi-turn troubleshooting to a diagnostic agent and an action agent. An offline mode runs the pipeline, its evaluation and the Streamlit UI without API keys.

Problem

A service answer depends on one subsection of one manual: a torque value in a specification table, a step in a seal replacement, an alarm code in a troubleshooting table. Retrieval that returns a passage from the wrong subsection, or from another machine's manual, produces an answer that reads as plausible and is wrong. The evaluation here measures that directly: whether the expected subsection of the named manual is among the top 5 passages.

Golden set: sample_data/golden_set.json, 15 questions, each with an expected subsection.

How it works

Manuals are parsed into a four-level chunk hierarchy and the level 4 chunks are embedded into Qdrant. A query runs vector search and, when enabled, Neo4j full-text search; each list adds weight / (k + rank) to a passage's score, with k=10 and weights 0.6 and 0.4. The top 5 passages go to the answer generator, which cites them as [Source N].

flowchart LR
  manuals[Manuals] --> parse[Parse and chunk] --> embed[Embed] --> qdrant[(Qdrant)]
  parse -.-> extract[Entity extraction] -.-> neo4j[(Neo4j)]
  question[Question] --> vsearch[Vector search]
  question -.-> gsearch[Graph search]
  qdrant --> vsearch
  neo4j -.-> gsearch
  vsearch --> rrf[Weighted RRF]
  gsearch -.-> rrf
  rrf --> answer[Answer with citations]

The agent layer runs on top of this pipeline. The supervisor classifies each message (troubleshoot, question, record, confirm_action, unclear) with the chat model or with keyword rules, and extracts the manufacturer, model and symptoms. The diagnostic agent rewrites the query, retrieves and re-ranks passages and forms hypotheses; the action agent records the session in the knowledge graph. Each specialist returns to the supervisor, which then writes the reply.

flowchart LR
  message[Message] --> supervisor[Supervisor]
  supervisor --> diagnostic[Diagnostic agent]
  supervisor --> action[Action agent]
  supervisor --> respond[Respond]
  diagnostic --> supervisor
  action --> supervisor
  diagnostic --> rag[Retrieve and re-rank]
  action -.-> session[(Neo4j session)]

Dashed paths run only with GRAPH_ENABLED=true, a Neo4j server and an OpenAI key.

Measured results

Offline baseline: hashing embedder, extractive answers and a lexical judge, on 3 synthetic manuals and 15 golden questions. The run is deterministic and CI fails if it changes. The scores measure lexical overlap and are not comparable with LLM-judged RAGAS scores.

Hosted run, 2026-10-30, one run: gpt-4.1-mini writes the answers and, as an LLM judge, scores them; embeddings are text-embedding-3-large. Same 3 manuals and 15 questions, with a Neo4j graph of 1,271 extracted nodes. Fused and vector retrieval returned the same top 5 for all 15 questions, because with weights 0.6 and 0.4 no graph result outranks the fifth vector result. Graph-only retrieval returns entity nodes, which carry no subsection, so its retrieval scores are 0 by construction.

Sources: results/offline-baseline.json and results/hosted-2026-10-30.json. Reproduce the baseline: LLM_MODE=offline uv run service-manual-rag ingest --reset, then uv run service-manual-rag evaluate --output results/offline-baseline.json. The hosted run: scripts/hosted_evaluation.py, as in the README.

Run it

  1. git clone https://github.com/darblinko/service-manual-rag
cd service-manual-rag
  2. uv sync --extra dev
  3. LLM_MODE=offline uv run service-manual-rag quickstart
  4. uv sync --extra dev --extra agents --extra ui
LLM_MODE=offline uv run service-manual-rag ingest --reset
LLM_MODE=offline uv run streamlit run ui/app.py

Limitations

  • 4 of 15 questions missed their expected section, including all 3 troubleshooting questions.
  • 53.3% of retrieved passages come from the manual the question names; retrieval does not filter by the model in the question.
  • Faithfulness is 100% by construction for extractive answers.
  • The vector, graph and fused comparison is one hosted run of 15 questions, judged by the same model that wrote the answers. With the default weights, graph results never reached the top 5.
  • Agent behaviour is covered by unit tests and a Streamlit page test, not by a measured evaluation. The diagnostic agent searches only when the conversation names a symptom or a manufacturer.
  • A script fetches three public-domain FAA PDFs (17 U.S.C. 105) and verifies their SHA-256 checksums. Indexing them was not run: Unstructured 0.27.35 routes all three to its hi_res layout model, which was not downloaded. No score on them is recorded.
  • The golden set covers 3 synthetic manuals. It detects regressions; it does not estimate accuracy on real manuals.
